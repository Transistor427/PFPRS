# PFPRS — Power Failure Print Recovery System

Восстановление печати после отключения питания для Klipper.
Поддержка OrcaSlicer, одноголовые и двухголовые принтеры Z-Bolt.

Во время печати модуль сохраняет позицию в файле, координаты, температуры и
контекст G-кода. После восстановления питания печать продолжается — либо
**автоматически**, если питания не было считанные секунды, либо по кнопке
после осмотра детали оператором.

---

## Что изменилось относительно v4

| | v4 | сейчас |
|---|---|---|
| Хранилище состояния | 12 вызовов `SAVE_VARIABLE` каждые 15 с, полная перезапись файла без атомарности | один атомарный JSON, два слота, `fsync` + `os.replace` |
| Продолжение печати | копия `restore.gcode` (сотни МБ на каждое восстановление) | оригинал файла через `virtual_sdcard`, копий нет |
| Абсолютный экструдер (`M82`) | `G92 E0` → выброс филамента на сотни мм | `G92 E<сохранённое>` |
| Контекст печати | сканирование префикса файла в RAM | снимается из живого статуса Klipper |
| Сетка стола, babystep, `M220`/`M221`, подача `F` | терялись | восстанавливаются |
| Проверка файла | нет | сверка размера и даты правки |
| После успешной печати | точка жила вечно, кнопка «восстановить» была активна всегда | точка инвалидируется |
| Переезд в точку останова | на высоте печати, сопло тащило через деталь | поднятым, опускание в конце |
| Зависший флаг восстановления | следующая печать молча без защиты | сторож по таймауту |
| `[save_variables]` | обязателен | не нужен |

Полностью автоматическое возобновление — новая функция, в v4 её не было.

## Установка

```bash
cd ~ && git clone -b v4 https://github.com/Transistor427/PFPRS/

# Python-модуль
sudo ln -sf ~/PFPRS/pfprs.py ~/klipper/klippy/extras/pfprs.py

# Конфиг (один из двух)
cp ~/PFPRS/pfprs.cfg ~/printer_data/config/klipper-config/pfprs.cfg
# cp ~/PFPRS/pfprs_dual.cfg ~/printer_data/config/klipper-config/pfprs_dual.cfg

sudo systemctl restart klipper
```

В `printer.cfg`:
```
[include klipper-config/pfprs.cfg]
```

Нужны `[virtual_sdcard]`, `[print_stats]`, `[respond]`.
`[save_variables]` больше не требуется.

### Возможные конфликты секций

Klipper не запустится при дубле секции. Проверьте перед включением:

- **`[force_move]`** в поставляемых `pfprs.cfg` / `pfprs_dual.cfg` закомментирован,
  потому что он почти всегда уже есть в `printer.cfg` или `steppers.cfg`.
  Раскомментируйте, только если у вас его нет. Требуется
  `enable_force_move: True` — без него не работает `SET_KINEMATIC_POSITION`.
- **`_PROMPT_END`** намеренно не объявляется: этот макрос определяет плагин
  timelapse. Для закрытия диалога используйте `_PFPRS_PROMPT_CLOSE`.
- `[save_variables]` PFPRS не трогает, но если он уже есть — оставьте как есть.

**Парковка осей.** Возьмите секцию `[homing_override]` из `homing.cfg`.
Без неё после отключения питания обычный `G28` поведёт ось Z вниз сквозь
напечатанное. Пока PFPRS держит блокировку, паркуются только X и Y.

Если `[homing_override]` у вас уже есть — не заменяйте его целиком, а добавьте
ветку по `printer.pfprs.emergency_homing`, оставив вызов своего макроса
парковки в ветке `else`. Параметры осей в него передавать нельзя: голое `X`
не является парой `key=value`, и Klipper ответит `Malformed command`.

### Обновление с v4

Старые опции (`history_size`, `save_delay`, `restore_filename`,
`moonraker_url`) модуль принимает и игнорирует, поэтому существующий
`printer.cfg` продолжит грузиться. Но лучше заменить секцию `[pfprs]` на
новую из `pfprs.cfg` — появились параметры, которых раньше не было.

Прежние имена команд и макросов сохранены: `PFPRS_QUERY_STATE`,
`PFPRS_CLEAR`, `SHOW_RESUME_INTERRUPTED`, `_RESUME_INTERRUPTED_CURR`,
`_PROMPT_END`, `_LOG_Z`, `HOMING_EMERGENCY`. Кнопки на панелях перенастраивать
не нужно.

Файлы `restore.gcode` от старой версии можно удалить — они больше не
создаются.

## Автоматическое возобновление

Идея простая: **температура активного хотенда показывает, сколько времени
не было питания.**

После загрузки Klipper модуль ждёт `auto_resume_delay` секунд (нужно, чтобы
термисторы дали устойчивые показания) и сравнивает фактическую температуру
активного хотенда с сохранённой целевой:

```
сохранённая цель − фактическая  ≤  auto_resume_temp_delta   →  восстановление автоматом
```

По умолчанию порог 20 °C. Сопло остывает с 240 °C быстро, поэтому уложиться
в него можно только если питание вернулось за считанные секунды. В этом
случае деталь заведомо на месте, пластик в точке останова не застыл, наплыв
образоваться не успел — вмешательство оператора не нужно. Сохранённая высота
Z принимается за верную: стол под собственным весом не смещается.

Восстановление запускается само: прогрев, парковка XY, возврат в точку
останова, продолжение файла.

### Когда автомат не сработает

Любое из условий уводит на ручной путь с диалогом:

- `auto_resume: False` в конфиге или `PFPRS_SET_AUTO_RESUME ENABLE=0`;
- хотенд остыл больше чем на `auto_resume_temp_delta`;
- сохранённая целевая температура ниже `auto_resume_min_target` (100 °C) —
  защита от бессмысленного сравнения;
- перед перезапуском была аварийная остановка: `M112`, ошибка MCU, любое
  событие `klippy:shutdown`. Причина остановки могла быть не связана с
  питанием, поэтому автомат тут запрещён. Снимается опцией
  `auto_resume_after_shutdown: True`;
- файл печати изменился или удалён;
- точка восстановления отменена или печать завершилась штатно.

### Кнопка аварийного останова

Нажатие аварийной кнопки (`M112`) — почти всегда осознанное решение оператора,
а не сбой питания. Поэтому такая остановка **снимает точку восстановления
полностью**: ни автоматики, ни диалога с предложением продолжить.

Отличается это по причине остановки, которую сообщает Klipper. Прочие
аварийные остановки — потеря связи с MCU, `Timer too close`, перегрев —
точку сохраняют: автомат блокируется, но ручное восстановление предлагается.

```
emergency_stop_discards: True
emergency_stop_markers: M112, emergency stop
```
Поставьте `emergency_stop_discards: False`, если хотите, чтобы восстановление
предлагалось и после нажатия кнопки.

### Включение и выключение

```
PFPRS_AUTO_ON       # включить
PFPRS_AUTO_OFF      # выключить
PFPRS_AUTO_TOGGLE   # переключить — удобно повесить на кнопку панели
```
Состояние сохраняется между перезагрузками и видно в `printer.pfprs.auto_resume`.
Команда `PFPRS_SET_AUTO_RESUME ENABLE=0|1` делает то же самое из сценариев.

### Диалог при ручном восстановлении

Появляется сообщение «Печать завершилась неудачно» с причиной и инструкцией:

1. осмотреть деталь — не отслоилась ли от стола, нет ли наплыва пластика в
   точке остановки (наплыв нужно срезать, иначе сопло об него ударится);
2. открыть панель **Действия → Движения → Аварийное перемещение** и выполнить
   действия по инструкции — парковка оси Z в этот момент заблокирована, сопло
   находится внутри детали;
3. нажать **Возобновить печать**.

Кнопка **Восстановить с калибровкой Z** (`RESUME_WITH_PROBE PLATE=1`) нужна,
если стол просел: зонд выставляет высоту по пластине известной толщины,
положенной на деталь.

Если макрос диалога по какой-то причине не определён, модуль всё равно
выведет ту же инструкцию текстом в консоль.

## Настройка

Полный список опций секции `[pfprs]` с комментариями — в `pfprs.cfg`.
Ключевые:

| Опция | По умолч. | Смысл |
|---|---|---|
| `save_interval` | 5.0 | как часто точка уходит на диск, с |
| `resume_lag` | 2.0 | откат точки назад для компенсации look-ahead буфера, с |
| `sample_interval` | 1.0 | как часто снимается срез состояния, с |
| `auto_resume` | True | автовозобновление |
| `auto_resume_temp_delta` | 20.0 | допустимое остывание хотенда, °C |
| `auto_resume_min_target` | 100 | ниже этой цели автомат не работает, °C |
| `auto_resume_after_shutdown` | False | автомат после `M112` / ошибки MCU |
| `verify_source` | True | сверять размер и дату файла |
| `restore_gcode_offset` | True | возвращать babystep после парковки |
| `arm_emergency_homing` | True | блокировать парковку Z, пока точка активна |
| `z_hop` | 5.0 | подъём перед парковкой, мм |
| `prime_length` / `prime_retract` | 20.0 / 1.0 | прайм и ретракт перед переездом, мм |
| `safe_home_temp` | 200 | до этой температуры греем перед парковкой XY, °C |
| `bed_mesh_fallback_profile` | — | профиль сетки, если имя не сохранилось |

### Адаптивная сетка стола

Если `START_PRINT` вызывает `BED_MESH_CALIBRATE ADAPTIVE=1`, Klipper создаёт
временный профиль с именем вида `adaptive-F5E3D730`. После перезапуска такого
профиля не существует, и `BED_MESH_PROFILE LOAD` по нему завершится ошибкой.

PFPRS распознаёт этот случай: имя берётся, только если профиль действительно
сохранён. Иначе поправка сетки (`mesh_comp = kin_z − z − offset_z`,
посчитанная в самой точке останова) вносится в **опорную высоту**, которую
получает `SET_KINEMATIC_POSITION`. Локально это эквивалентно сетке, потому
что печать продолжается в том же месте стола.

Принципиально: поправка **не** попадает в `SET_GCODE_OFFSET`. На
тулченджерах макросы `T0`/`T1` часто читают `homing_origin.z` как подстройку
оператора и записывают её в постоянную калибровку — компенсация сетки в
несколько миллиметров испортила бы настройки машины. В `SET_GCODE_OFFSET`
восстанавливается только истинный babystep.

Поле `printer.pfprs.z_ref` отдаёт готовую опорную высоту; `kin_z` остаётся
как диагностическое значение.

### О `save_interval` и `resume_lag`

`file_position` в Klipper опережает физически напечатанное на глубину
look-ahead буфера. Поэтому точка возобновления берётся не текущая, а на
`resume_lag` секунд назад: небольшое перекрытие безопаснее пропуска
материала.

Суммарное перекрытие при восстановлении — до `save_interval + resume_lag`
секунд печати. Значения по умолчанию дают около 7 секунд. Увеличивать
`save_interval` не нужно: запись компактная и атомарная, 5 секунд не
нагружают SD-карту.

## Команды

| Команда | Назначение |
|---|---|
| `PFPRS_STATUS` | показать сохранённую точку и результат проверки |
| `PFPRS_SAVE_STATE` | записать точку немедленно |
| `PFPRS_DISCARD` | удалить точку восстановления |
| `PFPRS_SET_AUTO_RESUME ENABLE=0\|1` | переключить автовозобновление |
| `PFPRS_CHECK_RECOVERY` | заново оценить возможность восстановления |
| `PFPRS_PREPARE_RESUME [GCODE_FILE=] [FORCE=1]` | проверить и подготовить файл |
| `PFPRS_BEGIN_RESUME` | восстановить контекст и продолжить печать |
| `PFPRS_ABORT_RESUME` | отменить подготовленное возобновление |
| `PFPRS_SET_EMERGENCY_HOMING VALUE=0\|1` | снять или поставить блокировку парковки Z |
| `PFPRS_ENABLE` / `PFPRS_DISABLE` | сохранение состояния |

Макросы: `SHOW_RESUME_INTERRUPTED`, `RESUME_WITH_PROBE PLATE=1`,
`PFPRS_RECOVERY_INFO`, `SET_Z_ZERO_POSITION`, `SET_Z_MAX_POSITION`.

`FORCE=1` обходит проверку идентичности файла. Пользуйтесь осознанно: если
файл действительно другой, сопло пойдёт в произвольную точку.

## Состояние для макросов и панелей

Модуль публикует `printer.pfprs` — координаты, температуры, имя файла,
позицию, номер слоя, флаги `valid`, `recovery_available`, `recovery_auto`,
`emergency_homing`, `temp_target`, `temp_actual`, `temp_drop` и параметры
движения. Полный список — в `get_status()` файла `pfprs.py`.

Пример кнопки в панели:
```
[gcode_macro TOGGLE_AUTO_RESUME]
gcode:
    {% if printer.pfprs.auto_resume %}
        PFPRS_SET_AUTO_RESUME ENABLE=0
    {% else %}
        PFPRS_SET_AUTO_RESUME ENABLE=1
    {% endif %}
```

## Совместимость со слайсером

Ничего добавлять в G-код не нужно — сохранение идёт по интервалу.

Строку `_LOG_Z Z=[layer_z]` в G-коде смены слоя OrcaSlicer можно оставить:
она форсирует внеочередное сохранение. Параметр `Z` теперь игнорируется —
точка всегда берётся с задержкой `resume_lag`, иначе компенсация буфера
теряется и на шве появится пропуск.

## Совместимость с тулченджерами

Если ваши макросы смены инструмента ведут собственный учёт Z-офсета (читают
`printer.gcode_move.homing_origin.z` и сохраняют отклонение через
`SAVE_VARIABLE`), проверьте после первого восстановления, что калибровка не
изменилась:

```bash
grep "^offset_z\|^t0offset\|^t1_z_offset" ~/printer_data/config/toolchanger-settings.cfg
```

PFPRS специально не кладёт компенсацию сетки в `SET_GCODE_OFFSET` именно
из-за такого учёта, но восстанавливаемый babystep эти макросы всё же увидят —
это корректно, он и есть подстройка оператора.

## Смежное: сторож масштаба скорости

В репозитории лежит `speed_guard.cfg` — **самостоятельный** конфиг, не
связанный с PFPRS ничем и работающий на любом принтере с Klipper.

Он решает отдельную проблему: OrcaSlicer при двухголовой печати выдаёт
`M220 S100` в начале каждого чернового столбика, и то же делают макросы
парковки голов, из-за чего скорость, выставленная оператором, сбрасывается
при каждой смене инструмента. Сторож запоминает значение перед машинным
сбросом и возвращает его после смены; осознанно выставленные оператором
100% при этом сохраняются.

```
[include speed_guard.cfg]
```
плюс `RESTORE_SPEED_FACTOR` последней строкой в макросы `T0`/`T1`.

## Обновление модуля

Klipper по команде `RESTART` пересоздаёт объекты, но **не переимпортирует
Python-модули** — они остаются в `sys.modules`. После правки `pfprs.py`
нужен полный перезапуск сервиса:

```bash
sudo systemctl restart klipper
```
Для правок в `.cfg` достаточно обычного `RESTART`.

## Удаление

```bash
sudo rm -f ~/klipper/klippy/extras/pfprs.py
rm -f ~/printer_data/config/klipper-config/pfprs.cfg \
      ~/printer_data/config/klipper-config/pfprs_dual.cfg
rm -rf ~/printer_data/pfprs
sudo rm -rf ~/PFPRS
```
Уберите `[include …]` и секцию `[homing_override]` из `printer.cfg`,
перезапустите Klipper.
