# PFPRS — Power Failure Print Recovery System

Восстановление печати после отключения питания для Klipper.
Одноголовые и двухголовые принтеры, слайсер OrcaSlicer.

Во время печати модуль записывает позицию в файле, координаты, температуры,
сетку стола, babystep, подачу и масштаб скорости. Состояние лежит в своём
каталоге двумя слотами: запись атомарная, обрыв питания портит только тот
слот, который писался в этот момент.

После включения возможны два пути:

- **автоматически**, если хотенд ещё горячий — питание не было считанные секунды, деталь на месте;
- **вручную**, диалогом с кнопкой, после осмотра детали.

Печать продолжается по исходному файлу через `virtual_sdcard`. Отдельная копия G-кода не создаётся.

---

## Что нужно принтеру

В `printer.cfg` уже должны быть:

```
[virtual_sdcard]
[respond]
```

`[print_stats]` Klipper поднимает вместе с `virtual_sdcard`.

Секция `[force_move]` с `enable_force_move: True` входит в `pfprs.cfg` и `pfprs_dual.cfg`. Она нужна команде `SET_KINEMATIC_POSITION`, которой восстанавливается высота Z. Если такая секция уже есть в другом файле, Klipper объединяет опции: остаётся значение из файла, прочитанного позже. В любом случае `enable_force_move` должно быть `True`.

Состояние пишется в `state_path` (по умолчанию `~/printer_data/pfprs/state`).

## Установка на одноголовый принтер

```bash
cd ~
git clone -b v6 https://github.com/Transistor427/PFPRS.git

sudo ln -sf ~/PFPRS/pfprs.py ~/klipper/klippy/extras/pfprs.py
cp ~/PFPRS/pfprs.cfg ~/printer_data/config/klipper-config/pfprs.cfg
```

В `printer.cfg`:

```
[include klipper-config/pfprs.cfg]
```

Парковка Z уже входит в `pfprs.cfg`. Дальше добавьте вызовы в макросы окончания и отмены — раздел [Что добавить в конфиг принтера](#что-добавить-в-конфиг-принтера). Затем:

```bash
sudo systemctl restart klipper
```

Проверка: в консоли `PFPRS_STATUS`. Ответ «сохранённого состояния нет» на простое — печати ещё не было. В объекте `printer.pfprs` поле `auto_resume` должно быть `true`, `dual` — `false`.

## Установка на двухголовый принтер

Тот же модуль, другой конфиг. В секции `[pfprs]` стоит `dual: True`, макрос восстановления выбирает активную голову и перед движением сверяет, что на слайдере стоит она.

```bash
cd ~
git clone -b v6 https://github.com/Transistor427/PFPRS.git

sudo ln -sf ~/PFPRS/pfprs.py ~/klipper/klippy/extras/pfprs.py
cp ~/PFPRS/pfprs_dual.cfg ~/printer_data/config/klipper-config/pfprs_dual.cfg
```

В `printer.cfg`:

```
[include klipper-config/pfprs_dual.cfg]
```

Подправьте под машину макрос `_PFPRS_VERIFY_TOOL` в `pfprs_dual.cfg`. Сейчас он читает кнопки `gcode_button t0_parking` и `gcode_button t1_parking`. Состояние `PRESSED` означает, что голова снята с парковки и стоит на слайдере. Если датчики называются иначе или логика инвертирована, замените имена и условие. При несовпадении головы восстановление останавливается: смена инструмента в этот момент не выполняется, её делают вручную и повторяют запуск.

Если после возврата в точку нужно выполнить машинный макрос (например `SKEW`), раскомментируйте в секции `[pfprs]`:

```
post_restore_macro: SKEW
```

Он вызывается уже после восстановления координат и температур, непосредственно перед продолжением файла.

Дальше — общие добавления из следующего раздела и перезапуск:

```bash
sudo systemctl restart klipper
```

`printer.pfprs.dual` должен быть `true`.

## Что добавить в конфиг принтера

Одноголовый и двухголовый варианты отличаются только подключаемым файлом. Пункты ниже одинаковы, если не сказано иное.

### Окончание печати

Первой строкой макроса `END_PRINT`:

```
PFPRS_PRINT_DONE
```

Если конечный G-код слайсера не вызывает макрос, а написан целиком в профиле принтера, та же команда ставится первой строкой конечного G-кода. Иначе остывание и парковка после готовой детали останутся в точке восстановления, и следующее включение предложит её продолжить.

### Отмена печати

Первой строкой макроса `CANCEL_PRINT`:

```
PFPRS_PRINT_DONE
```

То же самое, если отмена уходит в `RESTART`: точка должна быть снята до перезапуска.

### Парковка оси Z

Пока точка восстановления действительна, `G28` не должен опускать Z в деталь. Флаг `printer.pfprs.emergency_homing` включается при загрузке с живой точкой и на время подготовки возобновления. Снимается при старте продолжения, при `PFPRS_DISCARD`, при `PFPRS_ABORT_RESUME` и по таймауту `resume_timeout`. Вручную: `PFPRS_SET_EMERGENCY_HOMING VALUE=0`.

В одноголовом `pfprs.cfg` это уже делает макрос `G28`. Он нужен, потому что на таком принтере обычно есть `[safe_z_home]`, а вместе с `[homing_override]` Klipper эту секцию не загружает. Пока флага нет, команда выполняется как раньше: макрос передаёт её в `G28.1`, и отрабатывает прежняя парковка, включая `safe_z_home`. Отдельный файл для этого не подключается.

`homing.cfg` остаётся для принтера без `[safe_z_home]`, у которого обычный `G28` — это свой макрос `HOMING`. Туда переносится секция `[homing_override]`. Вместе с макросом `G28` из `pfprs.cfg` её не включают.

### Слайсер

В стартовый G-код ничего добавлять не нужно: сохранение включается само, когда `print_stats` переходит в `printing`.

В G-код смены слоя OrcaSlicer, если нужна запись на каждом слое, а не только по таймеру:

```
_LOG_Z
```

Параметр `Z` макрос не использует. Точка всё равно берётся на `resume_lag` секунд раньше текущего места в файле.

### Уход головы с траектории

Пока печать идёт, модуль пишет координаты головы. Если макрос уводит её в парковку — смена инструмента, кадр таймлапса, замена филамента — оберните этот участок:

```
PFPRS_HOLD
; парковка, смена, снимок
PFPRS_RELEASE
```

Пока удержание активно, точка на диске не меняется. После `PFPRS_RELEASE` окно `resume_lag` начинается заново, и в него не попадает стоянка.

### Диалоги

Макрос `_PROMPT_END` в конфиг PFPRS не входит. Его уже объявляет плагин таймлапса, а две секции с одним именем Klipper не загрузит. Закрытие диалога PFPRS — `_PFPRS_PROMPT_CLOSE`.

## Разбор конфига

Ниже секция `[pfprs]`. Оба файла содержат одни и те же опции; в `pfprs_dual.cfg` дополнительно `dual: True` и макросы двух голов. После правки `.cfg` достаточно `RESTART`. После правки `pfprs.py` нужен `sudo systemctl restart klipper`: команда `RESTART` не перечитывает уже загруженный Python-модуль.

### Сохранение

| Опция | По умолчанию | |
|---|---|---|
| `sample_interval` | 1.0 | как часто снимается срез состояния, с |
| `save_interval` | 5.0 | как часто срез пишется на диск, с |
| `resume_lag` | 2.0 | на сколько секунд назад берётся точка возобновления, с |
| `save_min_buffer` | 0.5 | при меньшем запасе движения в очереди шагов плановая запись откладывается, с |
| `save_max_defer` | 30 | дольше этого запись не откладывается, с |
| `resume_timeout` | 1800 | через сколько секунд снимается незавершённая подготовка восстановления |

`file_position` в Klipper опережает физически напечатанное на глубину look-ahead. Точка берётся не текущая, а на `resume_lag` секунд раньше: короткое перекрытие шва лучше пропуска материала. Суммарное перекрытие — до `save_interval + resume_lag` секунд. При значениях по умолчанию это около 7 секунд.

Файл состояния пишется с fsync в отдельном потоке, а не в потоке Klipper, поэтому медленная SD-карта не останавливает отправку шагов в MCU. Пока очередь шагов почти пуста (пробы `Z_TILT_ADJUST`, `BED_MESH_CALIBRATE`, парковка), запись откладывается. Если файл печати не продвинулся, одна и та же точка повторно не пишется.

`gcode_path` — каталог G-кода, по умолчанию `~/printer_data/gcodes`. Должен совпадать с `path` секции `[virtual_sdcard]`.

`state_path` — файл состояния без суффикса. Рядом появляются `state.0.json` и `state.1.json`.

`debug_mode: True` дублирует служебные сообщения в консоль.

### Автоматическое возобновление

Включение и выключение на работающем принтере:

```
PFPRS_AUTO_ON
PFPRS_AUTO_OFF
PFPRS_AUTO_TOGGLE
```

То же из макроса: `PFPRS_SET_AUTO_RESUME ENABLE=0` или `ENABLE=1`. Значение сохраняется в файле состояния и видно как `printer.pfprs.auto_resume`. Стартовое значение до первой записи задаёт опция `auto_resume` (по умолчанию `True`).

После готовности Klipper модуль ждёт `auto_resume_delay` секунд и сравнивает фактическую температуру активного хотенда с сохранённой целью:

```
сохранённая цель − фактическая  ≤  auto_resume_temp_delta
```

По умолчанию порог 20 °C, пауза 5 с, минимальная цель `auto_resume_min_target` — 100 °C. Ниже этой цели сравнение не выполняется.

Если условие выполнено, запускается `_PFPRS_AUTO_RESUME`: прогрев, парковка XY, возврат в точку, продолжение файла. Высота Z берётся из точки: за короткое отключение стол не смещается.

Ручной диалог вместо автомата появляется, когда:

- `auto_resume` выключено;
- хотенд остыл сильнее, чем `auto_resume_temp_delta`;
- сохранённая цель ниже `auto_resume_min_target`;
- перед выключением был `klippy:shutdown` (ошибка MCU, `Timer too close`, перегрев), а `auto_resume_after_shutdown` остаётся `False`;
- файл изменился или удалён (`verify_source: True` сверяет размер и дату);
- точка снята или печать до этого завершилась штатно.

`auto_resume_max_age` — максимальный возраст точки в секундах. `0` отключает проверку: у Pi без RTC часы после включения могут быть неверными.

`auto_resume_after_shutdown: True` разрешает автомат и после аварийной остановки Klipper. По умолчанию выключено: причина остановки могла быть не в питании.

Нажатие аварийной кнопки (`M112`) снимает точку целиком: ни автомата, ни диалога. За это отвечают

```
emergency_stop_discards: True
emergency_stop_markers: M112, emergency stop
```

`emergency_stop_markers` — подстроки текста остановки, который пишет Klipper (`Shutdown due to M112 command`). `emergency_stop_discards: False` оставляет такую остановку на ручном пути, как прочие shutdown.

### Восстановление контекста и движение

| Опция | По умолчанию | |
|---|---|---|
| `verify_source` | True | сверять размер и дату файла |
| `restore_gcode_offset` | True | вернуть babystep (`SET_GCODE_OFFSET`) |
| `arm_emergency_homing` | True | блокировать парковку Z, пока точка жива |
| `z_hop` | 5.0 | подъём перед переездом, мм |
| `z_lift_speed` | 600 | скорость подъёма и опускания, мм/мин |
| `travel_speed` | 6000 | скорость переезда XY, мм/мин |
| `prime_length` | 20.0 | прайм перед переездом, мм. `0` — без прайма |
| `prime_speed` | 2100 | скорость прайма, мм/мин |
| `prime_retract` | 1.0 | ретракт после прайма, чтобы нить не тянулась через деталь |
| `safe_home_temp` | 200 | до этой температуры греется активный хотенд перед парковкой XY |
| `min_active_temp` | 150 | на двух головах: ниже этой цели голова считается незадействованной |
| `chamber_heater` | chamber | имя `heater_generic` камеры. Пусто — камеру не трогать |
| `part_fan` | fan | вентилятор обдува детали |
| `bed_mesh_fallback_profile` | пусто | профиль сетки, если в точке имя не сохранилось |

Сетка с именем вида `adaptive-…` после перезапуска не существует: `BED_MESH_CALIBRATE ADAPTIVE=1` создаёт временный профиль. В точку попадает только имя, которое реально есть среди сохранённых профилей. Иначе поправка сетки в точке останова (`mesh_comp`) закладывается в опорную высоту `z_ref` для `SET_KINEMATIC_POSITION`. В `SET_GCODE_OFFSET` попадает только babystep: макросы смены инструмента часто читают `homing_origin.z` как постоянную калибровку оператора.

Если профиль сохраняется явно, например `BED_MESH_PROFILE SAVE=start_adaptive_mesh`, в точку пишется это имя и при восстановлении выполняется `BED_MESH_PROFILE LOAD`.

`restart_macro`, `prompt_macro`, `auto_resume_macro` — имена макросов прогрева, диалога и автостарта. Менять их нужно вместе с макросами в том же файле.

`post_restore_macro` — необязательный макрос перед продолжением файла. В одноголовом конфиге по умолчанию пусто.

### Ручное восстановление

Диалог предлагает:

1. осмотреть деталь: отслоение от стола и наплыв в точке остановки, наплыв срезать;
2. панель **Действия → Движения → Аварийное перемещение** — ось Z в этот момент заблокирована;
3. **Возобновить печать** (`SHOW_RESUME_INTERRUPTED`).

**Восстановить с калибровкой Z** (`RESUME_WITH_PROBE PLATE=1`) — если стол просел. `PLATE` — толщина пластины, положенной на деталь, в миллиметрах. Зонд принимает срабатывание за высоту детали плюс пластина. После срабатывания диалог просит убрать пластину и нажать «Продолжить».

Повторить оценку без перезагрузки: `PFPRS_CHECK_RECOVERY`. Текст инструкции без диалога: `PFPRS_RECOVERY_INFO`.

`PFPRS_PREPARE_RESUME FORCE=1` пропускает проверку файла. Координаты при этом остаются от сохранённой точки: другой файл приведёт сопло не туда.

## Команды

| Команда | Назначение |
|---|---|
| `PFPRS_STATUS` | точка, проверка файла, состояние автовозобновления |
| `PFPRS_SAVE_STATE` | записать точку сейчас |
| `PFPRS_DISCARD` | удалить точку и снять блокировку Z |
| `PFPRS_AUTO_ON` / `PFPRS_AUTO_OFF` / `PFPRS_AUTO_TOGGLE` | автовозобновление |
| `PFPRS_SET_AUTO_RESUME ENABLE=0\|1` | то же из макроса |
| `PFPRS_CHECK_RECOVERY` | заново решить, доступно ли восстановление |
| `PFPRS_PREPARE_RESUME` | проверить точку и открыть файл с нужного байта |
| `PFPRS_BEGIN_RESUME` | вернуть контекст и продолжить файл |
| `PFPRS_ABORT_RESUME` | отменить подготовку |
| `PFPRS_SET_EMERGENCY_HOMING VALUE=0\|1` | блокировка парковки Z |
| `PFPRS_ENABLE` / `PFPRS_DISABLE` | разрешить или остановить запись точки |
| `PFPRS_HOLD` / `PFPRS_RELEASE` | заморозить точку на время ухода головы |
| `PFPRS_PRINT_DONE` | снять точку. Первая строка `END_PRINT` и `CANCEL_PRINT` |
| `SHOW_RESUME_INTERRUPTED` | ручное возобновление |
| `RESUME_WITH_PROBE PLATE=1` | возобновление с калибровкой Z |
| `HOMING_EMERGENCY` | включить блокировку Z и припарковать только XY |

Для панели удобен `PFPRS_AUTO_TOGGLE`. Состояние для своих макросов — объект `printer.pfprs`: координаты, температуры, файл, слой, `valid`, `recovery_available`, `recovery_auto`, `recovery_reason`, `emergency_homing`, `temp_target`, `temp_actual`, `temp_drop`, `z_ref`. Полный набор полей — `get_status()` в `pfprs.py`.

## Удаление

Одноголовый принтер:

```bash
sudo rm -f ~/klipper/klippy/extras/pfprs.py
rm -f ~/printer_data/config/klipper-config/pfprs.cfg
rm -rf ~/printer_data/pfprs ~/PFPRS
```

Двухголовый — тот же набор, вместо `pfprs.cfg` удаляется `pfprs_dual.cfg`.

Из `printer.cfg` уберите строку `[include …]` этого файла. Если подключали `homing.cfg`, уберите и его секцию `[homing_override]`. Уберите вызовы `PFPRS_PRINT_DONE`, `PFPRS_HOLD`, `PFPRS_RELEASE`. Если `[force_move]` нужен другим макросам, секцию оставьте. Перезапустите Klipper:

```bash
sudo systemctl restart klipper
```
